# Naming remix notes from session

## User style constraints

- Use short, brandable title families.
- Prefer simple, outcome-first language.
- Avoid technical labels like developer, coding, programming, vibecode in course naming.
- Treat words like Arc, Rhythm, and Vector as conceptual buckets during ideation, not literal final title words.
- Let one strong lead word carry the brand; use the subtitle to explain the promise.
- Research-backed naming should surface actual market patterns before generating variants.

## Useful title families observed

- Blueprint
- Lab
- Academy
- Method / Protocol
- Workshop / Bootcamp

## Good title shapes

- Brand + shell: Builder Blueprint, Builder Lab, Builder Academy
- Brand + promise: Builder Blueprint: From Idea to Shipped MVP
- Event framing: Builder Bootcamp, Builder Workshop

## Pitfall

Do not convert internal concept buckets directly into final titles. If a user says a word is a design direction, treat it as an axis for variation, not a candidate name.
