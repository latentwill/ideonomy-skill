# Abstraction-lift

State the concrete idea, then replace domain-specific entities and actions with roles and relationships. Name the resulting process, topology, flow, or constraint. Preserve the relationships that matter; record what the abstraction leaves out. Probe another domain to assess transferability without forcing a match. A generic label alone is not a useful abstraction. Use the result as input to cross-domain re-instantiation; distinguish an observed structural match from a proposed analogy.

Adapted from Gunkel and Kind; see [sources](../../references/sources.md). [Examples](../../references/operator-examples.md#abstraction-lift) are optional.
